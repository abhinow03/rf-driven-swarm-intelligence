# data/

SFT (supervised fine-tuning) training/validation sets for the LLM fine-tuning pipeline
(`llm_finetuning/`), **not** RF or flight data — every file here is generated by
`llm_finetuning/build_sft_dataset.py`, which uses `RULES` (canonical decision logic) plus
teacher-model-distilled prose over synthetic tactical contexts. No raw sensor data of any
kind exists in this project.

Multiple versioned files exist (`sft_train.jsonl`, `_v2`, `_v3`, `_v3d`, `_final`,
`_final_abstain`, `_final_abstain_fix`) because each corresponds to a specific adapter
version's training run — see `docs/ADAPTER_VERSIONS.md` for exactly which file trained which
adapter and why each revision happened (e.g. `_abstain_fix` corrects a labeling bug in
`_abstain`). Kept rather than collapsed to "the latest one" because `AUDIT.md`'s dataset-ledger
section (sec C) and adapter-forensics section (sec B) reference specific files' row content
directly, and reproducing those sections requires the exact file they analyzed.

Regenerate any of these from scratch:

```bash
export GROQ_API_KEY=...
python llm_finetuning/build_sft_dataset.py --n 600 --out data/sft_train.jsonl
```

STGT's own training data (`swarm_data/`) is not in `data/` — it's generated by
`scripts/generate_data.py`, is not committed (`.gitignore`), and is not from this same
pipeline.
